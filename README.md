# HTTP Media Inspector - Инспектор мультимедийных файлов

Легковесное приложение на C++ для сканирования директории и отслеживания мультимедийных файлов (аудио, видео, изображения) с предоставлением результатов через HTTP API.

## Возможности

- Рекурсивное сканирование директории с использованием `fts_open()` (эффективный обход файловой системы)
- Поддержка форматов:
  - **Аудио**: mp3, wav, flac, ogg, m4a, aac, wma
  - **Видео**: mp4, avi, mkv, mov, wmv, flv, webm, mpeg, mpg
  - **Изображения**: jpg, jpeg, png, gif, bmp, tiff, webp, svg
- Фоновое периодическое сканирование (настраиваемый интервал)
- HTTP REST API endpoint `/media_files` с JSON-ответом
- Настраиваемые параметры: директория сканирования, порт, интервал
- Потокобезопасный доступ к данным (мьютекс + атомарный swap)

## Требования

- **Операционная система**: Linux (использует `fts.h` для обхода директорий)
- **Компилятор**: GCC 7+ или Clang 5+ с поддержкой C++17
- **Система сборки**: CMake 3.10+
- **Зависимости**: 
  - `pthread` (стандартная библиотека потоков)
  - `libc` (предоставляет `fts.h`)
  - `cpp-httplib` (header-only, уже включен в `lib/`)
  - `gtest` (опционально, только для тестирования)

## Сборка

```bash
# Клонирование репозитория
git clone https://github.com/AlexeyL54/HTTPMediaInspector.git
cd fileInspector

# Создание директории для сборки
mkdir build && cd build

# Конфигурация CMake
cmake ..

# Сборка
make

# Запуск (пример)
./httpMediaInspector -d /путь/к/директории -p 8080 -t 10

# Или с параметрами по умолчанию
./httpMediaInspector
```

## Использование

### Аргументы командной строки

| Опция | Описание | Значение по умолчанию |
|-------|----------|----------------------|
| `-d директория` | Путь для сканирования | Домашняя директория (`$HOME`) |
| `-t интервал_сек` | Интервал сканирования в секундах | 5 |
| `-p порт` | Порт HTTP-сервера | **1234** |
| `-h` | Показать справку | - |

### Примеры запуска

```bash
# Сканирование домашней директории с интервалом 5 секунд на порту 1234
./httpMediaInspector

# Сканирование указанной директории с интервалом 10 секунд
./httpMediaInspector -d /home/user/Music -t 10

# Сканирование с пользовательским портом
./httpMediaInspector -d /home/user/Videos -p 3000

# Полный набор параметров
./httpMediaInspector -d /media/data -t 30 -p 9090

# Показать справку
./httpMediaInspector -h
```

### HTTP API

После запуска сервера результаты сканирования доступны по адресу:

```
http://localhost:1234/media_files
```

#### Пример ответа

```json
{
  "audio": ["/home/user/song1.mp3", "/home/user/song2.wav", "/home/user/podcast.ogg"],
  "video": ["/home/user/movie.mp4", "/home/user/clip.avi"],
  "images": ["/home/user/photo.jpg", "/home/user/screenshot.png"]
}
```

> **Важно**: пути в ответе — абсолютные (как возвращает `fts_path`).

#### Тестирование API с `curl`

```bash
# Получить все медиафайлы
curl http://localhost:1234/media_files

# Отформатированный вывод (требуется jq)
curl -s http://localhost:1234/media_files | jq '.'

# Проверить только аудиофайлы
curl -s http://localhost:1234/media_files | jq '.audio'
```

## Тестирование

Проект включает набор тестов на Google Test. Для сборки и запуска тестов:

```bash
cd tests
mkdir build && cd build
cmake ..
make
./test
```

### Тесты покрывают

- Пустая директория → корректный пустой JSON
- Обнаружение аудио, видео и изображений
- Игнорирование файлов с неподдерживаемыми расширениями
- Динамическое обновление при добавлении/удалении файлов
- Рекурсивное сканирование поддиректорий
- Корректная остановка сервера
- Конкурентный доступ (20 параллельных запросов)
- Пользовательские интервал и путь
